# Contribution Guidelines

Welcome to the **Intraday Trading Simulator Engine** project!  
This project thrives on clean architecture, modular design, and community energy. Your PR—big or small, wild idea or bugfix—has the power to make this simulation platform smarter and better for everyone.

***

## Code Philosophy

- **Abstraction First:**  
  Keep things loosely coupled and make features easy to extend. If your addition feels like a one-off hack, consider how abstraction or interfaces might help.
- **Modularity:**  
  New features, metrics, or algorithms should be easy to plug in, swap out, or combine with existing code.
- **Scalability:**  
  Code for the future! A solution that works for one stock or one type of ML model should adapt for many.

***

## Code Quality Guidelines

- **Meaningful Names:**  
  Choose variable and function names that actually describe what they do. No more `foo` or `temp2`.  
- **Use Comments Wisely:**  
  Add helpful comments if something is tricky or could trip up the next contributor. Clarity is king.
- **No Heavy In-Code Documentation Needed:**  
  For this repo, there’s no need for exhaustive docstrings or formal code docs. But…

***

## Pull Request (PR) Expectations

- **Clear, Detailed PR Descriptions:**  
  Every PR should *clearly* explain:
  - What you changed or built
  - Why you did it this way
  - Any considerations for abstraction or scalability
  - Any issues/ideas you want feedback on  
- **Context Matters:**  
  Make your PR easy for maintainers and reviewers to understand—imagine they’ve never seen this part of the code before.

***

## Tests? Relax.

This is a hack-heavy, experimental repo.  
**You don’t have to add tests or demos.**  
Focus on coding with modularity, abstraction, and scalability in mind.

***

## Just Bring Value!

- **Cool ideas? Try them out and raise a PR!**  
- **See a bug, typo, or code smell? Fix it (even small).**  
- **Quality > quantity. Even the smallest refactor helps.**

***

## Communication

- No idea is too strange. Pitch it in your PR, or start an Issue for collaboration.
- Questions, discussions, memes, and code critiques are welcome.

Thanks for building something awesome with us!
